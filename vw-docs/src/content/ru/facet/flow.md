## for

```facet
for app in state.apps key app.id {
    ui.Text(text: app.name)
}
```

`for` повторяет своих детей для каждого элемента любого диапазона C++. `key` задаёт, что идентифицирует элемент: по нему Facet привязывает [анимации](/ru/facet/animation/) и элементы управления, так что они следуют за элементом, когда список меняет порядок. Без `key` используется позиция элемента.

## if

```facet
if state.loading {
    ui.Spinner()
} else if state.error != null {
    ui.Text(text: state.error, color: "#fa746f")
} else {
    ui.Text(text: "Готово")
}
```

Ветка может ничего не рисовать; раскладки вокруг справятся с пустым списком.

## let

```facet
for metric in state.metrics {
    let critical = metric.value >= 90
    ui.Text(text: metric.name, color: critical ? "#fa746f" : "#dfe6ee")
}
```

`let` даёт имя значению для элементов после него в том же блоке.

В начале файла, вне всех view, `let` создаёт константу, которой может пользоваться любой view файла:

```facet
let gap = 10
let accent = "#a7cbe7"

view Bar(state) {
    ui.Text(text: state.title, color: accent)
}
```

## Имена элементов: id

`id:` с простым именем даёт элементу имя. Его дети и элементы после него в том же блоке читают через это имя его размеры и положение, так что они зависят друг от друга, а не повторяются числами:

```facet
let gap = 8

ui.Surface(id: bar, width: 0, height: 32, anchor: top) {
    layout.Row(id: row, width: bar.width - gap * 2, height: bar.height, gap: gap, align: center) {
        ui.Text(id: title, text: state.title)
        // всё, что заголовок оставил от строки
        ui.Rectangle(width: row.width - title.width - gap, height: 4, color: "#a7cbe7")
    }
}
```

| Через имя | Что это |
| --- | --- |
| `x`, `y`, `width`, `height` | обычные числа, у любого элемента |
| `props` | всё, что элементу передали, плюс значения по умолчанию: `panel.props.variant` |
| `built` | измерен ли уже размер |

Размеры зависят от того, где их читают:

- **Внутри элемента** (в его детях) — это то, что элемент запросил: `bar.width` выше — ширина монитора, потому что `width: 0` заполняет его. Незаданный размер там равен `0`.
- **После элемента** (в следующих соседях и всём ниже) — это **измеренные** размеры: `title.width` — ширина, которой текст получился на самом деле, а `row.width` — строка после раскладки.

Имя видно только ниже места, где оно дано; ссылаться вперёд нельзя. Положение детей внутри `Row`, `Column` или `Grid` окончательно только после того, как раскладка построена, поэтому их соседи видят место, где они созданы, а не то, куда их поставит раскладка. Два элемента в одном блоке не могут иметь одно имя.

У элемента управления `id: "search"` (строка) или переменная по-прежнему задаёт ключ его состояния; элементу даёт имя только ещё не занятое имя.

## properties

В начале файла `properties(id: name) { … }` задаёт свойства элемента с именем `id: name`: во view остаётся структура, а размеры, цвета и положения лежат отдельно — как таблица стилей для одного элемента:

```facet
properties(id: panel) {
    variant: "panel"
    width: 200
    height: 100
    place: { x: 10 }
}

view Bar(state, actions) {
    S.Surface(id: panel, place: { y: 20 }) { … }
}
```

Свойства пишутся по одному на строку, с запятыми или без. То, что элемент задаёт сам, важнее; объект, заданный в обоих местах, сливается по полям, так что панель выше стоит в `x: 10, y: 20`. В значениях можно использовать `let` уровня файла и имена других элементов (`panel.height - 34`), как и в самом элементе. Блок `properties` для имени, которого нет ни у одного элемента, — ошибка.

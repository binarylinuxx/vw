## Блокировка

Функция сборки, вызывающая `ui.session_lock()`, просит композитор заблокировать сеанс; `ui.lock_surface()` отмечает, что рисовать на каждом мониторе.

```cpp
bool locked = false;  // ставится хоткеем, сигналом, таймером простоя…

app.surface([&](vw::Ui& ui) {
  if (!locked) return;                       // ничего не рисует: блокировки нет
  ui.session_lock({.on_unlock = [&] { locked = false; }});
  ui.lock_surface();
  const vw::LockSurfaceContext output = vw::lock_surface_context();
  const float w = output.width, h = output.height;
  ui.rectangle({.width = w, .height = h, .color = vw::rgb(0x101419)});  // сначала непрозрачное
  ui.text_field({.id = "password", .placeholder = "Пароль", .width = 320,
                 .password = true, .authenticate = true, .autofocus = true,
                 .place = {.x = (w - 320) / 2, .y = h * 0.6f}});
});
```

Функция вызывается один раз для каждого монитора; `lock_surface_context()` говорит, для какого и какого он размера. Сначала нарисуйте что-то полностью непрозрачное — ничто позади блокировки не должно быть видно.

## Аутентификация

Текстовое поле с `authenticate = true` проверяет своё значение через PAM при нажатии Enter. Успех снимает блокировку, уничтожает поверхности блокировки и вызывает `on_unlock`; там уберите то, из-за чего сборка рисовала блокировку. Без `on_unlock` разблокировка завершает приложение.

- `vw::session_authentication_failed()` истинно после неверного пароля и до следующей попытки — потрясите поле, покажите ошибку.
- `pam_service` по умолчанию `swaylock`, если существует `/etc/pam.d/swaylock`, иначе `login`; `pam_conf` может указывать на ваш собственный файл PAM.
- `on_authenticated(bool)` у поля сообщает о каждой попытке.

## Полезные привычки

- Пусть первая клавиша только показывает поле пароля, а не печатает в него: привычный пробел или Enter не должен попасть в пароль.
- Очищайте поле после периода без ввода.
- Анимации появления — поверх непрозрачной основы, никогда не вместо неё.

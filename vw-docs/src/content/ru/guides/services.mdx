## Схема

Каждый сервис работает в своём потоке: главный цикл GLib для сервисов D-Bus (NetworkManager, BlueZ, UPower, MPRIS, трей, уведомления), собственный цикл PipeWire, inotify для подсветки, сокеты для композиторов. Когда его состояние меняется, он обновляет снимок и делает свой fd событий читаемым.

- **Чтение дешёвое.** `vw::network::status()`, `vw::mpris::active()`, `vw::upower::display_device()` возвращают кэшированный снимок; они никогда не блокируются на шине. Вызывайте их из функций сборки сколько угодно.
- **Запись — это вызовы.** `set_wifi_enabled`, `set_volume`, `play_pause`, `set_powered` обращаются к сервису и возвращают, получилось ли; само изменение приходит обратно событием.
- **События объединяются.** `drain_events()` опустошает fd и возвращает `true`, если что-то произошло; после этого приложение один раз пересобирает все поверхности.

Ваши собственные источники подключаются так же: любой fd плюс функция, которая его опустошает и говорит, нужна ли пересборка, — signalfd, inotify, timerfd.

```cpp
app.on_event(signal_fd, [] { /* прочитать siginfo */ return true; });
```

<Callout type="note">
Отрицательный fd (сервиса нет в этой системе) игнорируется, так что регистрировать всё без условий — нормально.
</Callout>

Вызов `ui.surface(props)` в функции сборки делает поверхность layer-поверхностью. vw говорит по `wlr-layer-shell-v1`, а когда доступен — по родному layer shell zwwm.

## Привязка, размер, резерв

```cpp
const vw::Size output = vw::surface_size();  // {0, 0} до первого configure
ui.surface({.width = 0,                       // 0: на всю ширину, решает композитор
            .height = 40,
            .anchor = vw::anchor::top,
            .layer = vw::Layer::top,
            .exclusive_zone = 40,             // окна не заходят на эти 40 px
            .surface_namespace = "my-bar"});
```

- **Размер.** Не задавайте `width`/`height` — и поверхность будет размером с нарисованное. `0` растягивает её по этой оси (привязываются оба края), а размер выбирает композитор; узнать его можно через `vw::surface_size()` и раскладывать относительно него.
- **Anchor** — набор битов: `top`, `bottom`, `left`, `right`, углы или `fill`.
- **Слой**: `background`, `bottom`, `top`, `overlay`.
- **Margin** — `{top, right, bottom, left}` от привязанных краёв.
- **Exclusive zone** резервирует место от привязанного края. Она может быть меньше поверхности, так что панель может раскрыться, не расталкивая окна; `-1` полностью игнорирует зоны других поверхностей (обои, полноэкранные оверлеи).
- **Namespace** — то, по чему срабатывают правила слоёв композитора (размытие, анимации).

## Клики насквозь

`input_regions` перечисляет прямоугольники (`{x, y, width, height}`), которые принимают указатель. Всё вне них проходит к окнам ниже. Пустой список делает всю поверхность прозрачной для кликов; если поле не задано, ввод принимается везде.

```cpp
std::vector<std::array<std::int32_t, 4>> input = {{0, 0, (int)output.width, 40}};
if (panel_open) input.push_back({x, 40, 360, 480});
ui.surface({.width = 0, .height = 0, .anchor = vw::anchor::fill, .exclusive_zone = -1,
            .input_regions = std::move(input)});
```

Так одна полноэкранная поверхность может рисовать рамку, панель и выезжающие панели, а середина экрана остаётся доступной.

## Клавиатура

Layer-поверхности получают клавиши, только когда просят. `ui.keyboard(handler, mode)` ставит обработчик клавиш и выбирает запрос:

| Режим | Значение |
| --- | --- |
| `automatic` | `on_demand`, если в сцене есть текстовое поле или обработчик клавиш, иначе `none` |
| `none` | никогда не берёт клавиши |
| `on_demand` | получает фокус по клику, как окно |
| `exclusive` | захватывает клавиатуру, пока видна (лаунчеры, меню) |

Обработчик видит каждую клавишу первым и возвращает `true`, если обработал её; остальное уходит в текстовое поле с фокусом.

## Попапы, закрывающиеся по клику мимо

С zwwm `focus_grab = true` просит композитор сообщить, когда пользователь кликнул в другом месте. `on_dismiss` получает `FocusEvent`, у которого `reason()` — `outside`, `unmapped`, `replaced`, `locked` или `released`; там и закрывайте попап. Подробнее в [Захват фокуса и декорации](/ru/compositor/zwwm-surfaces/).

## Панель на каждый монитор

`app.per_output(build)` создаёт поверхность для каждого монитора и передаёт функции сборки этот монитор, так что панель знает свою ширину с самого первого кадра, а не ждёт configure от композитора:

```cpp
app.per_output([&](vw::Ui& ui, const vw::Output& output) {
  // узкому экрану ноутбука — компактная панель
  const bool compact = output.width < 1600;
  const vw::Widget clock = ui.text({.text = clock_text(), .size = compact ? 13.0F : 15.0F});
  ui.align(clock, vw::anchor::center);
  if (!compact) build_workspaces(ui, output.name);
  ui.surface({.width = 0, .height = 32, .anchor = vw::anchor::top, .exclusive_zone = 32});
});
```

Каждая поверхность попадает на свой монитор (`SurfaceProps::output` заполняется за вас). Подключённый позже монитор получает свою панель, у отключённого она пропадает, а смена режима или масштаба пересобирает их. Остальные остаются как есть.

Чтобы поставить одну поверхность на выбранный монитор, задайте `output` сами: `ui.surface({…, .output = "HDMI-A-1"})`. `vw::outputs()` перечисляет имена и размеры. В Facet это `Surface(output: "HDMI-A-1", …)`, а view может принимать монитор параметром: `views::Bar(ui, state, output)`.

## Появление и исчезновение

Сборка, которая ничего не нарисовала, оставляет поверхность скрытой, пока следующая сборка снова что-то не нарисует. Сделайте лаунчер зависимым от своего `bool open` — поверхность будет появляться и исчезать вместе с ним. Несколько вызовов `app.surface(...)` дают несколько поверхностей в одном цикле.

<Callout type="tip" title="Статичные поверхности">
Ставьте большой `refresh_interval` (до 3600 с) поверхностям, которые меняются только по событиям, — резервам у краёв, докам, — чтобы цикл не пересобирал их по таймеру.
</Callout>
